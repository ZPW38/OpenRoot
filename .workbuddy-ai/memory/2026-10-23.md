# 2026-10-23

## ADB 无线调试配对（已修复）
- 根因一：platform Conscrypt 的 `Java8EngineSocket` 不是 `org.conscrypt` socket，隐藏 API 反射被拦。
  改为 `SslUtils.getPairingSslContext()` 用内置 `org.conscrypt.OpenSSLProvider` 建 context，直接调 `Conscrypt.exportKeyingMaterial`。
- 根因二：vendored ed25519 的 `scalarMultiply`/`madd` 路径算错（`1*B` 都不是基点），SPAKE2 消息不是曲线点。
  已删除 `crypto/ed25519` 包，改为自写 `crypto/spake2/Ed25519Group.java`（BigInteger 扩展坐标，统一加法公式），
  `Spake2Context` 只用 M/N 压缩编码常量（`5ada7e4b…` / `10e3df0a…`）。主机 JVM + Python 参考实现双跑对齐。

## 主界面
- 设备信息卡（`ui/DeviceInfoCard.kt`，多张独立玻璃卡片）：Device / Chip / Kernel / SELinux，
  通过 ADB `getprop`+`uname -r`+`getenforce` 获取（`device/DeviceInfo.kt`），未连接时用本机属性兜底。
  注意：`getprop <不存在的 key>` 不输出任何行，必须用 `echo '@@'` 标记分隔，否则字段会错位；
  另外 `getprop`（无参全量）输出过大时 `AdbStream.read` 会卡住，所以只查单项。
- `AdbShell`：`AdbStream.read` 用 IOException("Stream closed.") 表示对端关闭，不是返回 -1，需要 catch。
- 顶部加 "OpenRoot" 左对齐标题，卡片整体下移；按钮高度 50dp。

## 临时 root（接入 ghostlock 原生载荷）
- `native/` 放了 C++ 核心（`core/` + `Makefile`），用 NDK r27d 的 make 编译：
  `NDK_ROOT=D:/android-ndk-r27d make -C native ghostlock`，产物 478KB arm64 ELF。
  需在 `core/kernel/constants.hpp` 里 `#undef PAGE_SIZE`（NDK sysroot 有同名宏）。
- 产物进 `app/src/main/jniLibs/arm64-v8a/libghostlock.so`；Gradle 任务 `buildNativeExploit`/`prepareNativeExploit`/`stripNativeExploit`。
- 内核 profile：73 个 GLK1 `.bin` 在 `app/src/main/assets/kernel_profiles/`，按 `uname -r` 精确匹配。
  生成方式（离线，一次性）：kotlinc 编译 ghostlock 的 `profile-core`，跑 `ProfileExporter` 导出。
- `root/RootExploit.kt`：push 载荷+profile 到 `/data/local/tmp/openroot`，以 shell 身份执行
  `./libghostlock.so --load-prebuilt-profile profile.bin`，输出走 `ui/ExploitLogCard.kt` 实时显示。
- `.github/workflows/android.yml` 增加 NDK r27d（nttld/setup-ndk）并给 gradle 传 `ANDROID_NDK_HOME`。

## 双引擎 + ksud 注入（10/24）
- 引擎一（native/，内核 profile）：`RootExploit` 增加 `GHOSTLOCK_KSUD` / `GHOSTLOCK_KSU_LOG`，
  跑完读 ksu 日志判 `KernelSU module loaded`，成功后 `KsuManager.launchManager()` 拉起管理器。
- 引擎二（native-df/，page cache CVE-2026-43284）：`exp.c`+`bootstrap.c`+`ko/*.ko` 用 NDK 直编
  （`native-df/Makefile`）。关键改动：
  - 预编译 .ko 里硬编码 `/data/user_de/0/df.root/bootstrap`，改成 `/data/local/tmp/dfroot/bootstrap`
    （等长以内补 NUL，脚本已跑过 8 个 ko）。
  - bootstrap.c 的 KSUD_STAGE/PREFS_PATH 改成 `#ifndef` + 默认 `/data/local/tmp/dfroot/*`。
  - 运行时由 ADB 通道把 bootstrap/ksud/dfroot.xml 放到 /data/local/tmp/dfroot（app 无写权限），
    再在 app 进程里建 IpSec 变换后 exec `libdfroot.so`。
- 支持状态：`SupportState{NotConnected,Supported,Candidate,Unsupported}`；profile 精确匹配才算
  Supported；只有 DirtyFrag 能试时显示 **Untested**（琥珀色问号），首次运行结果记到
  `ExploitMemory`（按 uname -r），下次据此显示 Supported/Unsupported。
- UI：Exploit 按钮 `fillMaxWidth` 与卡片平齐、蓝色；日志卡从底部悬浮移到按钮下方。
- Gradle 任务合并为 `buildNativeExploit`+`buildNativeDirtyFrag` → `prepareNativePayloads`（唯一写
  jniLibs 的任务）→ `stripNativePayloads`，避免两个任务同时写 jniLibs 触发校验失败。
- 状态徽标动画：`StatusBadge` 用 `Animatable` 0→1（1.5s，LinearEasing），`startAngle = 720° * t`
  让高亮弧转两圈，t 到 1 时 `drawCircle(accent)` 铺满、图形转深色；NotConnected 不动画也不填充。
- 注意：用户贴的 `prepareNativeDirtyFrag` / `stripNativeExploit` 报错是重构前的旧日志，
  现脚本只有 `prepareNativePayloads` + `stripNativePayloads`（单任务写 jniLibs）。

## 引擎选择 / 无 KernelSU 模式（10/24 下半场）

  所有 adb 命令/输出以 `<adb>` 前缀打进日志卡。
- 引擎选择层 `ui/EnginePicker.kt`（同 Composition 内全屏遮罩 + 玻璃卡），点 Exploit 弹出：

- 无 KernelSU 模式：`native-df/bootstrap.c` 增加 root 命令守护进程（fork+setsid，轮询
  `/data/local/tmp/dfroot/cmd`，输出到 `out`，完成后 touch `done`），prefs 里 `su_manager=none` 时走这条路径。
  App 侧 `root/RootShell.kt` 写 cmd→轮询 done→读 out；日志卡带一行命令输入框。
- 日志卡：占满剩余高度（`weight(1f)`）、内部滚动、按级别着色（info 灰 / error 红 / warning 琥珀 / success 绿）。

- `AdbShell` 加空闲看门狗（exec 15s / stream 120s），daemon 不响应时不会把调用方挂死。
- 日志改为"真实终端"：`AdbShell.stream` 用 `shell,pty:`（行缓冲、实时），失败回退管道；
  日志行只有两类——`$ 命令`（灰）和设备真实输出（按级别着色）。去掉所有 `<i>/<adb>/<pm>` 自造描述。
- `RootShell.run` 边轮询 out 文件边按行回显（250ms），长命令也实时。
- 支持判定改为检查 `nativeLibraryDir` 里是否真有 libghostlock.so / libdfroot.so（模拟器会谎报
