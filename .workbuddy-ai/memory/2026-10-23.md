# 2026-10-23

## ADB 无线调试配对（已修复）
- 根因一：platform Conscrypt 的 `Java8EngineSocket` 不是 `org.conscrypt` socket，隐藏 API 反射被拦。
  改为 `SslUtils.getPairingSslContext()` 用内置 `org.conscrypt.OpenSSLProvider` 建 context，直接调 `Conscrypt.exportKeyingMaterial`。
- 根因二：vendored ed25519 的 `scalarMultiply`/`madd` 路径算错（`1*B` 都不是基点），SPAKE2 消息不是曲线点。
  已删除 `crypto/ed25519` 包，改为自写 `crypto/spake2/Ed25519Group.java`（BigInteger 扩展坐标，统一加法公式），
  `Spake2Context` 只用 M/N 压缩编码常量（`5ada7e4b…` / `10e3df0a…`）。主机 JVM + Python 参考实现双跑对齐。

## 主界面
- 设备信息卡（`ui/DeviceInfoCard.kt`，多张独立玻璃卡片）：Device / Chip / Kernel / SELinux，
  通过 ADB `getprop`+`uname -r`+`getenforce` 获取（`device/DeviceInfo.kt`），未连接时用本机属性兜底。
  注意：`getprop <不存在的 key>` 不输出任何行，必须用 `echo '@@'` 标记分隔，否则字段会错位；
  另外 `getprop`（无参全量）输出过大时 `AdbStream.read` 会卡住，所以只查单项。
- `AdbShell`：`AdbStream.read` 用 IOException("Stream closed.") 表示对端关闭，不是返回 -1，需要 catch。
- 顶部加 "OpenRoot" 左对齐标题，卡片整体下移；按钮高度 50dp。

## 临时 root（接入 ghostlock 原生载荷）
- `native/` 放了 C++ 核心（`core/` + `Makefile`），用 NDK r27d 的 make 编译：
  `NDK_ROOT=D:/android-ndk-r27d make -C native ghostlock`，产物 478KB arm64 ELF。
  需在 `core/kernel/constants.hpp` 里 `#undef PAGE_SIZE`（NDK sysroot 有同名宏）。
- 产物进 `app/src/main/jniLibs/arm64-v8a/libghostlock.so`；Gradle 任务 `buildNativeExploit`/`prepareNativeExploit`/`stripNativeExploit`。
- 内核 profile：73 个 GLK1 `.bin` 在 `app/src/main/assets/kernel_profiles/`，按 `uname -r` 精确匹配。
  生成方式（离线，一次性）：kotlinc 编译 ghostlock 的 `profile-core`，跑 `ProfileExporter` 导出。
- `root/RootExploit.kt`：push 载荷+profile 到 `/data/local/tmp/openroot`，以 shell 身份执行
  `./libghostlock.so --load-prebuilt-profile profile.bin`，输出走 `ui/ExploitLogCard.kt` 实时显示。
- `.github/workflows/android.yml` 增加 NDK r27d（nttld/setup-ndk）并给 gradle 传 `ANDROID_NDK_HOME`。
