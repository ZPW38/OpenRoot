## KernelSU 交接修复（用户："执行 cve 漏洞获取临时 root 后有没有打开 kernelsu"）

- 新增 `root/RootHandoff.kt`：读 bootstrap 的 /dev 标记（dfm6=KSU / dfm7=回退命令通道 /
  dfm1=仅跑过 / dfme*=失败阶段），带轮询（GPU/PCT 20s，page cache 30s，因为模块 exec bootstrap 是异步的）；
  只有 `id` 返回 uid=0 才算命令通道可用。
- `native-or/bootstrap.c`：late-load 失败（dfme2）不再丢弃 root，改为起 root 命令通道 + `touch /dev/dfm7`。
- `native/core/attack/ops.cpp` + `runtime_config`：新增 `GHOSTLOCK_KSU_PKG` → 脚本 `KSU_PKG`，
  late-load 带 `--package-name`（与 bootstrap 路径对齐），日志加 `pkg=`。
- `KsuManager`：`launchManager` 返回 `LaunchResult`（NO_PACKAGE/NO_INTENT/FAILED），
  新增 `launchWithRetry`（等 /proc/modules 出现 kernelsu、最多 3 次、失败原因写日志卡）。
- MainActivity：四个引擎共用一次 `KsuManager.resolve`；三个引擎返回 `RootHandoff.Result`，
  统一 `reportHandoff()`：KSU→拉起管理器 / COMMAND→开命令通道 / NONE→退出码。
  `DirtyFragRunner` 不再用 `/dev/df`（那只是"加载模块"阶段标记，ksud 失败也会误判成功）。
- 新增字符串 `exploit_ksu_manual`（模块加载了但管理器没打开时提示手动打开）。
